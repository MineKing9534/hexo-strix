# Action-effect JEPA for lean-D6 axis-graph KLENT

Status: design proposal for critique and stress-testing. This document does not
authorize implementation. It replaces the abandoned value-grounded SPR plan.

## Decision summary

Add a training-only, action-conditioned joint-embedding prediction objective to
the graph-native Strix architecture and full-joint KLENT regime defined by
`configs/klent/axis-gine/s4-from-mc25-tau16-alpha001-full-batch2048.toml`:

```text
four-layer, 128-wide lean-D6 axis-relational graph trunk
    -> 512-wide per-node JK-cat representation
    -> policy and per-action Q heads trained by KLENT
    -> Gumbel MCTS using the exact Rust engine at deployment
```

For an on-policy state `s` and a legal candidate placement `a`, the Rust engine
constructs the exact immediate successor `T(s, a)`. A small graph predictor sees
the current trunk representation, the current axis graph, and only a marker on
the candidate node. It predicts the candidate-dependent representation change
after that placement. A permanently frozen copy of the branch-point trunk
encodes exact successors and supplies stop-gradient targets. Comparisons between
candidates from the same source cancel the graph-global phase transition and
isolate what changed because one legal placement was selected instead of
another.

```text
current graph s                         exact Rust transition
     |                                         |
     v                                         v
online lean-D6 trunk H(s)          successor graph T(s, a)
     |                                         |
candidate marker at node a                     v
     |                              target lean-D6 trunk H_bar(T(s, a))
     v                                         |
small lean-D6 graph predictor                   | stop-gradient
     |                                         |
     +---- match pairwise successor deltas -----+
```

The auxiliary asks:

> Can the representation express how this particular placement changes the
> board's learned structural features?

It does not ask the network to predict a future value, opponent response, future
trajectory, or terminal outcome beyond the immediate deterministic transition.

## Central hypothesis

KLENT supplies strong task grounding but teaches action consequences indirectly:

```text
policy: full improved-policy target over legal placements
Q:      TD(lambda) target for the played placement
```

The action-effect objective supplies an immediate causal constraint:

```text
state representation + candidate placement
    -> candidate-dependent component of the exact post-placement representation
       relative to other legal placements from the same state
```

If useful, this should arrange the shared trunk into a representation where
placement effects are simple and predictable. The ordinary policy and Q heads
can then reuse features that distinguish line extension, blocking, frontier
growth, and threat changes under both within-turn and turn-handoff phases.

The desired benefit is better representation learning, not learned planning:

```text
exact engine       = legal transitions
action-effect JEPA = action-sensitive feature learning
KLENT              = search-free policy and Q learning
Gumbel MCTS        = explicit deployment-time planning
```

## Why this replaces value-grounded future prediction

The previous proposal conditioned on a current placement and predicted the
Q-field at a later self-play position. It had three undesirable properties:

1. Later positions depended on sampled opponent and self-play continuations.
2. Q-readout agreement intentionally discarded structural differences between
   positions with similar values.
3. It attempted to amortize information that Gumbel MCTS already obtains more
   faithfully by branching through exact successor states.

MCTS backs scalar leaf estimates through a conditional tree, retaining which
reply produced which continuation. A deterministic feed-forward future-value
forecast averages or aliases that branch structure. It may be useful for a
strictly search-free agent, but it is a poor fit for the present objective:
improving a graph network that is already deployed inside exact-engine search.

Each uncentered successor is a property of `(s, a)` alone:

```text
T(s, a) is uniquely defined by the rules engine.
```

The centered training residual also references a deterministic set of legal
alternatives from `s` to remove their common phase transition. It still contains
no opponent policy, sampled continuation, or scalar strategic bottleneck.

## Scope

### In scope

- The graph-native lean-D6 axis-relational representation.
- The four-layer, hidden-width-128, JK-cat architecture family.
- KLENT policy/Q training on on-policy self-play states.
- Exact one-placement successors generated by the Rust engine.
- The played placement plus a small number of legal counterfactual placements.
- A training-only D6-preserving graph predictor.
- Stop-gradient action-contrastive residuals from a fixed target trunk.
- Graph-node correspondence by engine coordinate metadata.
- Collapse, shortcut, gradient-conflict, cost, and playing-strength diagnostics.
- Deployment evaluation with the existing Gumbel MCTS pipeline.

### Explicitly out of scope

- CNN, raster, dense-axis, or persistent-ray backends.
- Future Q-field, scalar V, Win/Loss, or value-equivalence targets.
- Opponent modelling or opponent-action conditioning.
- Multi-turn prediction.
- Learned subgoals or hierarchical goal selection.
- MCTS, expert checkpoints, or offline expert games as JEPA supervisors.
- Predicting raw board tensors, legal masks, or engine features directly.
- Using the JEPA predictor during inference.
- Replacing or approximating the Rust transition engine at deployment.
- Changing Gumbel MCTS, the exported policy/Q contract, or forcing logic.

### Lean node schema

The current model uses side-to-move-relative node features with:

```text
own stone
opponent stone
placements remaining this turn
inverse distance to the nearest stone
four own/opponent threat features
```

The redundant empty bit and normalized coordinates are absent. Absolute axial
coordinates remain graph-builder metadata for ordering and correspondence; they
are not model inputs.

### Axis relations and exact D6 symmetry

Real nodes are connected by the three unoriented hex-axis relation types and an
unsigned hop-distance embedding. Every axis uses the same message function and
the three axis contributions are combined by a symmetric sum. A separate dummy
node and global relation provide graph-wide communication.

At node level the representation is equivariant to the permutation induced by a
D6 transformation. Policy/Q results attached to corresponding legal nodes are
therefore invariant to the physical orientation.

The JEPA path must preserve this contract exactly. It may not consume normalized
coordinates, oriented axis identities, signed directions, or a raster action
plane.

### JK-cat representation

Each of the four 128-wide message-passing layers contributes a normalized node
embedding to Jumping Knowledge concatenation:

```text
H(s) has shape [number of graph nodes, 4 * 128]
     = [number of graph nodes, 512]
```

The policy and Q heads both read the 512-wide representation of legal-action
nodes. The action-effect objective should improve this shared representation
without sending auxiliary gradients into either output head.

## What constitutes one action

The KLENT action is one atomic legal placement, not a two-placement HeXO turn.
The immediate transition has two phase classes:

```text
first placement:
    moves remaining 2 -> 1
    side to move stays the same

second placement:
    moves remaining 1 -> 2
    side to move changes
    own/opponent-relative features change perspective
```

These are both legitimate one-step dynamics, but they are qualitatively
different prediction problems. Every loss, shortcut diagnostic, and retrieval
metric must be reported separately by source phase.

The predictor receives an explicit learned embedding of the source phase. This
is D6-invariant and permits candidate effects to differ between within-turn and
turn-handoff placements. Phase alone cannot solve the primary loss because that
loss compares candidates from the same source and phase.

## Training examples

### Source states

Use a bounded subset of ordinary on-policy KLENT self-play states. No future
trajectory is required. A source example consists of:

```text
source GameState s
stored played action a_played
stored KLENT policy target over legal actions
```

Assign whole trajectories to training or held-out JEPA diagnostics before
selecting source states. This prevents adjacent positions from the same game
appearing in both populations.

Sample source states evenly between first-placement and second-placement phases
where the collected data permits it. Record any residual imbalance.

### Counterfactual candidate placements

Using only the realized played placement permits a predictor to exploit action
frequency and state correlations. The exact engine permits stronger
self-supervision: generate several legal successors from the same source.

The provisional candidate set per selected source is:

1. The placement actually sampled during self-play.
2. One other placement sampled from the stored improved policy.
3. One uniformly sampled legal placement.

Deduplicate candidates. Positions with too few legal actions simply use all
available actions. Sampling is deterministic from the run seed, iteration,
trajectory index, and step index.

These choices are provisional and belong in the Phase 0 profile. Their purpose is
coverage, not strategic supervision. Q values, MCTS visits, expert labels, and
future actions do not choose or label the counterfactuals.

For each candidate:

```text
s_prime = clone(s)
s_prime.apply_move(a)
```

The target is generated from this exact engine state whether or not self-play
actually chose `a`.

### Why counterfactuals matter

For a fixed source representation, different candidates must predict different
successor residual fields:

```text
H(s), a_1 -> H_bar(T(s, a_1))
H(s), a_2 -> H_bar(T(s, a_2))
H(s), a_3 -> H_bar(T(s, a_3))
```

This supplies a direct action-sensitivity test. A predictor that ignores the
candidate cannot satisfy all targets unless the learned representation itself
ignores the board changes.

## Source and successor graph correspondence

One placement changes more than a node feature:

- The selected legal node becomes a stone node.
- New legal frontier nodes may appear.
- Threat features can change at multiple coordinates.
- Blocker-aware axis relations can change.
- At turn handoff, side-relative features swap globally.
- The target graph can have a different number and ordering of nodes.

The predictor runs on the current graph and therefore produces one predicted
delta for every current node. The target encoder runs on the exact successor
graph. Correspondence between real nodes is established by absolute axial
coordinate as loss metadata only.

Coordinates must never enter the predictor or trunk. Under a D6 transform, the
coordinate map is transformed solely to recover the equivalent node
permutation.

### Target scopes

Do not define affected nodes by asking whether the complete raw lean vector
changed from source to successor. `moves_remaining` is copied onto every real
node and changes after every placement; at handoff, side-relative ownership
changes globally as well. That rule would label nearly the entire graph and
turn the task into phase prediction.

Instead, construct all nonterminal candidate successors for a source first.
For every source coordinate, compare its successor feature and incident-edge
records *across candidates from that same source*. A retained node is
candidate-dependent when at least two candidate successors disagree at that
coordinate. Common changes shared by every candidate, including the phase
transition, do not enter this mask.

Use three explicit target scopes.

#### 1. Candidate coordinates

Every sampled candidate coordinate exists as a legal node in the source. In one
successor it is the newly placed stone; in the other candidate successors it
remains legal. Evaluate every candidate prediction over this same complete set
of coordinates. Their centered differences form the primary target scope.

These nodes are maximally action-specific and are directly related to the legal-
node embeddings that the policy and Q heads used to score the candidates.

#### 2. Candidate-dependent retained nodes

For coordinate-matched real nodes, compare candidate-successor records. Include
a node in the shared per-source mask when at least two successors disagree in
either:

- Their raw lean feature vector at that coordinate, or
- Their multiset of incident `(relation kind, unsigned distance, neighbour
  coordinate)` records.

The comparison is successor-to-successor, not source-to-successor, so a global
phase or perspective change common to every candidate is removed by
construction. The mask is exact-graph loss metadata and is never a predictor
input. All sampled candidate coordinates are always included. If the cap is
reached, sample the remaining coordinates deterministically from the shared
mask so every candidate pair is compared over the same coordinate set.

Report mask composition by the observed source of disagreement: occupancy,
inverse-distance/frontier, threat-only, and edge-topology. If almost all useful
fit is confined to threat-only nodes, the auxiliary may merely be forecasting
the existing hand-engineered threat calculator.

#### 3. Global dummy node

Compare successor dummy-node changes across candidates. It summarizes
candidate-dependent effects that are not expressible solely at retained local
nodes, including differences in newly introduced frontier nodes.

The pairwise comparison cancels the dummy node's common phase value. The dummy
target does not solve the new-node problem perfectly, but it exposes aggregate
candidate differences without requiring the predictor to invent a variable set
of nodes.

### New successor-only nodes

The MVP does not directly predict embeddings for nodes absent from the source
graph. Creating those nodes would require either:

- Giving the predictor successor topology from the engine, which makes the task
  substantially easier and changes its meaning, or
- Learning a variable-size node generator, which is unnecessary complexity for
  the first experiment.

Their influence is still visible in the target embeddings of retained nodes and
the global dummy after successor message passing.

Whether omission of direct new-frontier targets removes too much of the useful
signal is a central Phase 0 question.

## Target encoder

Let `E_theta` be the online lean-D6 trunk used by policy and Q. Let `E_bar` be a
non-gradient target copy with identical architecture.

For Phase 0 and the first bounded trunk-updating experiment, `E_bar` is copied
once from the precommitted branch checkpoint and then remains fixed for the
entire experiment:

1. Load the ordinary KLENT branch checkpoint strictly.
2. Copy its trunk weights into `E_bar`.
3. Set every target parameter non-trainable and keep it out of every optimizer.
4. Never refresh it during the bounded continuation.

This fixed teacher makes the target meaning identical in control diagnostics,
null auxiliaries, and the action-conditioned treatment. It also prevents a
moving online/target pair from lowering the loss by jointly making unused
channels action-invariant. Online-to-target drift is measured explicitly; if it
becomes large enough to invalidate the target, that ends the bounded run rather
than silently changing the teacher.

Generation-copy and EMA teachers are deferred ablations. They add a target
dynamics question before the fixed-teacher objective has shown any benefit and
are not part of this MVP.

All target forwards run in evaluation and inference mode. Target outputs are
FP32 for loss computation and are stop-gradient by construction.

## Predictor architecture

### Inputs

The predictor receives:

- `H = E_theta(s)`, the current 512-wide JK-cat node representation.
- The current lean axis graph relations and unsigned distances.
- A binary candidate marker attached to exactly one legal node.
- A learned embedding of whether one or two placements remain.
- The identity of the dummy node as already defined by the graph structure.

It does not receive:

- Successor node features or topology.
- A future legal mask.
- Target embeddings.
- Raw axial coordinates.
- Absolute or signed axis directions.
- Policy, Q, value, visits, outcome, or future actions.

### D6-preserving transition module

The provisional predictor is:

1. A shared per-node projection from 512 channels to 128.
2. Addition of learned candidate and phase embeddings.
3. Two residual `AxisRelationalConv` blocks with tied weights across the three
   axes and symmetric axis aggregation.
4. A shared per-node projection from 128 back to 512.

The output is a predicted representation delta for each current node:

```text
Delta_hat(s, a) = P(H(s), current_graph, candidate_marker(a), phase(s))
```

The predictor must use the same unsigned distance table size and global-relation
semantics as the base graph family. It has independent parameters; it does not
share convolution weights with the online or target trunk.

The final delta projection should start at zero. This starts from no predicted
candidate-dependent effect rather than from a random transition.

### Why a graph predictor is required

A per-candidate MLP could learn only from the candidate node and a pooled graph
summary. That would be cheap, but it could not express how a placement changes
features at other line-connected nodes. Reusing the invariant axis relation
structure lets the auxiliary propagate the candidate marker along the same
geometric pathways that make the production model strong.

Using an ordinary GINE with oriented edge attributes, raw coordinates, or an
untied MLP per axis would silently destroy the architectural D6 guarantee and is
not an acceptable shortcut.

## Prediction target and loss

For each source with at least two nonterminal candidates, encode every exact
successor with the fixed target trunk:

```text
B_a(v)     = stop_gradient(E_bar(T(s, a), v))
Delta_a(v) = predictor(E_theta(s), graph(s), a, phase(s))
```

`v` denotes a source coordinate retained in every candidate successor. Remove
the component common to the sampled candidates from both targets and
predictions:

```text
R_a(v)     = B_a(v) - mean_b(B_b(v))
R_hat_a(v) = Delta_a(v) - mean_b(Delta_b(v))
```

The mean is computed only as part of the loss over candidates already sampled
for that source. The predictor API remains `current representation + one
candidate marker`; it never receives the other candidates or any successor.
Centering is equivalent to supervising all pairwise successor differences while
avoiding quadratic work. It cancels action-independent phase and perspective
changes and also makes an unchanged source embedding useless as a retrieval
shortcut. The source target encoding is needed only for Phase 0 raw-delta
diagnostics or if the optional absolute term is later approved.

The target remains the rich 512-wide JK-cat representation rather than a scalar
value or Q readout. Phase 0 must measure candidate-dependent variance in each
128-wide JK segment. Only segments with nontrivial held-out variance enter the
first trunk-updating objective; inclusion of all four is not assumed.

### Residual distance

For each selected JK segment `k`, estimate a robust residual scale from the
Phase 0 training population and freeze that scale before comparing models:

```text
scale_k = median positive RMS norm of R_a,k

L_repr(a, v, k) = SmoothL1(
    (R_hat_a,k(v) - R_a,k(v)) / max(scale_k, epsilon)
)
```

This retains magnitude information and remains defined for small residuals.
Cosine agreement and raw RMSE are diagnostics, not substitute objectives.

Normalize each scope independently. Crucially, every candidate prediction is
evaluated over the same coordinate set:

```text
V_action  = all sampled candidate coordinates
V_changed = shared candidate-dependent retained-node mask excluding V_action

L_action  = mean loss over candidates and every coordinate in V_action
L_changed = mean loss over candidates and every coordinate in V_changed
L_global  = mean loss over candidates at the dummy node

L_JEPA = w_action  * L_action
       + w_changed * L_changed
       + w_global  * L_global
```

Using all candidate coordinates for every prediction prevents the metric from
comparing one physical node with a different physical node. The candidate scope
should have the largest initial weight. Exact coefficients are set from Phase 0
residual scales and then frozen before the continuation.

The MVP has no absolute successor-embedding loss. Such a term would deliberately
teach the shared phase transition as well as action effects and is an explicit
owner decision listed below, not an implicit addition.

### No full-graph invariance loss

There is no loss matching every current node to every successor node. Unchanged
nodes would dominate and reward copying. There is also no loss between unrelated
states, future self-play positions, or policy/value outputs.

### Candidate discrimination

For candidates from the same source, measure whether each centered predicted
residual field is closest to its own centered target residual field over one
shared coordinate mask:

```text
distance(R_hat_i[V], R_i[V]) < distance(R_hat_i[V], R_j[V])
```

Report retrieval for `V_action`, `V_changed`, and their union. This is initially
a held-out diagnostic, not another training loss. It must beat zero residual,
candidate-removed, and within-source shuffled-marker baselines. If retrieval
remains near chance while representation loss falls, the predictor is ignoring
action identity; do not rescue the result with a contrastive term in the MVP.

## Terminal transitions

The existing graph builder rejects terminal states because they have no legal
action graph. Silently dropping terminal candidates would remove the most
decisive placement effects.

The MVP handles a terminal successor with one training-only binary readout from
the predicted candidate and dummy features:

```text
wins_after_action: 0 or 1
```

This is an exact immediate engine label, not a future value target. There is no
`winner_is_actor` output: after `apply_move`, an immediate win can only belong to
the actor, making that proposed label constant. A terminal candidate is omitted
from latent centering and matching because no target graph exists. A source
with fewer than two nonterminal candidates contributes only to the terminal
loss. Terminal and nonterminal candidate counts and losses are reported
separately.

An alternative is extending the graph representation to encode terminal states.
That is architecturally cleaner but broadens the production graph contract and
should not be smuggled into the JEPA MVP without a separate decision.

## Collapse and shortcut control

The base policy/Q objectives ground the online trunk, and the target trunk is
fixed, but neither fact proves the auxiliary is useful.

### Required shortcut baselines

Evaluate the held-out centered-residual loss and retrieval under:

1. Correct candidate marker.
2. Candidate marker removed.
3. Candidate marker moved to another legal node from the same source.
4. Zero predicted residual.
5. A separately fitted predictor whose online-trunk input was detached for its
   entire training run.

Useful action-effect learning requires a persistent advantage for the correct
candidate over zero and shuffled candidates. A one-off forward pass with a
detached tensor is not a baseline: detaching changes backward propagation but
cannot change the prediction or held-out loss.

### Representation health

Track separately for online source, prediction, and target populations:

- Per-channel standard deviation.
- Covariance off-diagonal energy.
- Effective rank and leading singular-value share.
- Mean norm per JK segment.
- Raw target-delta and centered-residual norm per scope and phase.
- Fraction of near-zero centered residuals.

Variance/covariance regularization is not assumed in the first equation. Add it
only if the diagnostics show collapse or severe redundancy, and then ablate it
separately. A lower JEPA loss is not evidence that the representation improved.

### Predictor capacity

There is a tension:

- Too weak: it cannot express axis-line consequences, so noisy auxiliary
  gradients push the trunk toward an impossible target.
- Too strong: it learns the complete transition itself and leaves the trunk
  unchanged.

Two 128-wide relational blocks are a provisional middle point, not a conclusion.
Predictor-only target fit and trunk-gradient measurements must be used to decide
whether capacity is appropriate.

## Gradient flow and optimization

The combined training objective is:

```text
L_total = L_policy
        + q_loss_weight * L_Q
        + jepa_loss_weight * L_JEPA
        + terminal_loss_weight * L_terminal
```

Gradient ownership:

```text
policy loss -> online trunk + policy head
Q loss      -> online trunk + Q head
JEPA loss   -> online trunk + action-effect predictor
terminal    -> online trunk + predictor + terminal readout
target      -> no gradients
```

JEPA must not update policy or Q head parameters directly.

The MVP uses no auxiliary-only optimizer steps and no predictor learning-rate
multiplier. The current trainer schedules one common learning rate across all
parameter groups and records metrics under that assumption. The predictor and
terminal readout therefore use the same scheduled LR and weight decay as the
base network. A multiplier is a later optimizer ablation, not a hidden exception
to the matched continuation.

During a trunk-updating experiment, each JEPA backward is accumulated into the
same optimizer group as the ordinary policy/Q backward for that outer batch.
There is still exactly one optimizer step per existing outer KLENT batch. This
prevents extra AdamW steps, weight decay, and moment evolution from becoming a
treatment confound.

Choose `jepa_loss_weight` by its trunk-gradient contribution, not the raw loss
magnitude. The initial safety target should keep the JEPA trunk gradient a small
fraction of the combined policy/Q trunk gradient. Record:

- Policy-only trunk gradient norm.
- Q-only trunk gradient norm.
- JEPA-only trunk gradient norm.
- Cosine between JEPA and policy gradients.
- Cosine between JEPA and Q gradients.
- Combined trunk gradient norm and per-objective contribution ratios.
- Non-finite gradient or skipped-optimizer-step counts.

If JEPA gradients repeatedly oppose both task objectives, dominate the total
trunk update, or cause non-finite steps, reduce or stop the auxiliary rather
than introducing clipping or waiting for playing strength to fail. The loss
weight, source count, and chosen JK segments are frozen after the Phase 0 gate;
changing them during a continuation starts a new experimental arm.

## D6 contract and tests

For every one of the 12 D6 transformations:

1. Transform the `GameState` with the engine.
2. Transform the candidate coordinate.
3. Build source and exact successor lean graphs independently.
4. Run online, target, and predictor paths.
5. Undo the induced node permutations through coordinate metadata.
6. Compare predicted residuals, target residuals, scope masks, and losses.

The following must be invariant within the established numerical tolerance:

- Candidate-node prediction.
- Global prediction.
- Candidate-dependent mask membership after coordinate correspondence.
- Per-scope losses.
- Candidate retrieval ranking.
- Terminal prediction.

No augmentation is needed to teach the symmetry. These tests protect the exact
architectural property already supplied by tied axis weights and symmetric
aggregation.

## Training data and compute budget

The ordinary KLENT policy/Q FIT continues to use every retained collected
position. JEPA uses only a deterministic bounded subset distributed across the
existing outer batches.

Provisional production-shaped limits for measurement are:

```text
source states per iteration:       2,048
held-out source states:              256
maximum candidates per source:         3
maximum shared retained nodes:        32
```

At the configured 131,072 positions and batch size 2,048, the nominal epoch has
64 outer optimizer batches. After the ordinary deterministic shuffle, select up
to 32 eligible JEPA sources from each outer batch, yielding at most 2,048 source
states. Compute their normalized auxiliary mean inside that same optimizer
group. Do not concentrate all auxiliary examples in one update, repeat them
across every update, or add predictor-only updates during a trunk experiment.

These counts are budgeting hypotheses, not committed defaults. The first dry
profile must measure:

- Rust clone/apply and graph-construction time.
- Online source-encoder work that can be shared with KLENT FIT.
- Target source-encoder work for Phase 0 raw-delta diagnostics only.
- Target successor-encoder work per candidate.
- Predictor forward/backward time.
- Peak GPU allocation and reservation.
- Host memory used by retained GameStates and graph metadata.
- Compile specialization and graph-break counts.

The principal cost is target encoding of counterfactual successor graphs, not
the exact engine transition. Report both positions-to-strength and wall-clock-
to-strength; an apparent sample-efficiency gain can still lose on total compute.

## Checkpoint and deployment contract

The existing `model_state_dict` namespace remains exactly the deployable KLENT
network: online trunk, policy head, and Q head only. Predictor, terminal readout,
and fixed target trunk must not be registered beneath that model because the
current MCTS adapter reconstructs the plain network and loads it strictly.

Training checkpoints add a separate `jepa_state_dict` namespace containing:

- Predictor and terminal-readout parameters.
- The fixed target-trunk parameters.
- Branch-checkpoint path and SHA-256.
- Candidate sampling and held-out split seeds/counters.
- Selected JK segments, residual scales, scope weights, and loss weight.

The ordinary `optimizer_state_dict` contains two ordered parameter groups in a
JEPA run: existing model parameters first and new trainable auxiliary parameters
second. Both groups use the same scheduled LR. The fixed target is absent.

Initial branching from an ordinary checkpoint must proceed in this order:

1. Construct the plain model and its base optimizer group.
2. Strictly restore the ordinary `model_state_dict` and optimizer state.
3. Construct the auxiliary modules and copy the fixed target from the restored
   trunk.
4. Add the fresh auxiliary parameter group without changing existing parameter
   IDs, AdamW moments, counters, or LR.

Resuming a JEPA checkpoint constructs both ordered groups before strictly loading
the saved optimizer state, then loads `jepa_state_dict`. Candidate sampling and
the fixed teacher must reproduce exactly. This requires an explicit JEPA-aware
resume path; the current generic resume path is not assumed to handle it.

Deployment export remains unchanged:

```text
exported:
    online lean-D6 trunk
    policy head
    Q/value adapter required by the current Gumbel MCTS pipeline

discarded:
    target trunk
    action-effect predictor
    terminal auxiliary readout
    JEPA optimizer and sampling state
```

The predictor is not called at MCTS roots or leaves. The Rust engine continues
to construct every searched successor exactly.

## Phase 0: frozen-checkpoint probe

Several design gates require code, but none requires changing the production
network. Phase 0 is a diagnostic implementation with a hard prohibition on
updates to the branch checkpoint's trunk, policy head, or Q head. It precedes
authorization for a KLENT continuation.

### Dataset freeze

Select and hash one intact checkpoint from the target full-joint run. Collect a
fixed diagnostic corpus from that checkpoint, split by whole game, and retain
the exact source `GameState`, phase, candidate coordinates, successor states,
coordinate maps, and mask metadata. No expert or future trajectory labels are
used.

The initial profile compares one, two, and three candidates per source. Any
learnability claim uses at least two nonterminal candidates because centered
action residuals are undefined with fewer than two.

### Target audit

Before fitting a predictor, measure by phase, scope, and JK segment:

- Raw source-to-successor delta and centered action-residual distributions.
- Zero-residual error and chance retrieval.
- Shared mask sizes and their occupancy/frontier/threat-only/topology makeup.
- Fraction and latent influence of successor-only frontier nodes.
- Terminal-candidate frequency.
- Fixed-target D6 parity for all 12 transformations.

If no JK segment has material candidate-dependent residual variance, stop. An
absolute transition objective could still learn phase, but the proposed action-
effect hypothesis would have failed.

### Frozen-trunk predictor probes

Train small predictors while detaching `E_theta(s)` for their complete fits:

1. Correct candidate marker.
2. Candidate marker removed.
3. Candidate marker permuted within the same source.
4. Zero residual with no fitted predictor.

Compare a candidate-node MLP, one relational block, and two relational blocks.
Select the smallest model that produces a durable held-out correct-marker gap.
Because every trunk input is frozen for this phase, these fits test target
learnability and predictor capacity without claiming representation improvement.

### Phase 0 exit gate

Do not authorize trunk updates unless all of the following hold:

- Correct-marker residual error and retrieval materially beat marker-removed,
  shuffled-marker, and zero-residual baselines on held-out games.
- The advantage exists outside threat-only mask entries.
- At least one JK segment is informative without requiring all four.
- The current-topology predictor handles retained-node and dummy effects well
  enough that successor-only nodes are not the dominant missing signal.
- D6 parity holds for targets, predictions, masks, and retrieval.
- Measured target-forward and predictor cost leaves a credible wall-clock case.

Phase 0 produces the selected predictor capacity, JK segments, residual scales,
scope weights, source count, and a measured JEPA trunk-gradient budget for a
later continuation. Those values are precommitted before any playing-strength
run.

## Trunk-updating experimental design

Precommit the same branch checkpoint, target corpus rules, and hyperparameters,
then run four matched arm types in the initial safety pilot:

```text
control:
    ordinary KLENT

predictor-only:
    identical KLENT and auxiliary compute
    + correct candidate targets
    + JEPA input detached from the online trunk for the complete continuation

action-null:
    identical KLENT and auxiliary compute
    + deliberately uninformative action conditioning

action-effect:
    identical KLENT and auxiliary compute
    + correct candidate-conditioned centered-residual loss
```

The exact action-null construction is an owner decision below. It must retain
the same predictor parameter count, target forwards, loss normalization,
optimizer steps, and candidate distribution as the action-effect arm.

The predictor-only continuation differs from the Phase 0 probe: ordinary KLENT
still updates the deployed network, but JEPA receives `stop_gradient(E_theta(s))`
for its entire fit and therefore cannot update the trunk. It controls for target
encoding, predictor optimization, memory pressure, and wall-clock exposure. A
single forward-time detach toggle is not evidence; detachment is fixed for the
whole arm.

Keep the target configuration's collection size, terminal-only self-play,
tau/alpha/beta, KLENT epochs, base learning rate, lack of gradient clipping,
evaluation openings, opponent suite, and Gumbel MCTS budgets matched. Each arm
performs the same number of base optimizer steps. Report auxiliary wall-clock
cost rather than pretending ordinary KLENT and JEPA are compute-identical.

One seed may be used only as a short four-arm safety pilot. A causal strength
claim requires replicated continuations from the same branch checkpoint with
precommitted independent run seeds. If the predictor-only pilot tracks control
and shows no pipeline confound, the recommended minimum main experiment is
three seeds for control, action-null, and action-effect. If it does not, retain
predictor-only as a fourth replicated arm.

### Evaluation contract

Evaluate the resulting deployable model without loading auxiliary state:

1. Raw-policy argmax play.
2. Raw-Q argmax play, implemented as a distinct selector.
3. Low-budget Gumbel MCTS.
4. The configured 24-simulation, 8-action deployment budget.
5. Direct action-effect versus control, predictor-only, and action-null games.
6. Fixed historical checkpoints and the unchanged branch checkpoint.

Use paired, colour-swapped, seeded openings. The configured `best_so_far` and
lag-5 opponents remain useful health telemetry but are endogenous to each arm;
they are not matched evidence of a between-arm advantage. Do not infer strength
from policy, Q, or JEPA losses.

### Evidence required to continue

Continue beyond the bounded experiment only if:

- Correct conditioning retains its Phase 0 advantage over null conditioning.
- Representation rank and variance remain healthy.
- JEPA gradients remain subordinate to and not persistently antagonistic with
  both KLENT objectives.
- KLENT optimization remains stable with no extra optimizer steps.
- Replicated paired evaluations show a credible playing-strength or learning-
  speed advantage over ordinary KLENT and action-null, while predictor-only
  tracks the ordinary control closely enough to rule out a pipeline confound.
- The benefit remains credible in wall-clock-to-strength, not only positions-to-
  strength.

### Evidence to reject or redesign

Stop or redesign if:

- Centered-residual loss falls without a correct-vs-null action gap.
- Zero residual remains competitive with the fitted predictor.
- The action-effect deployed model does not improve over the predictor-only arm,
  indicating that auxiliary trunk gradients supplied no benefit.
- Useful fit is confined to hand-engineered threat-only changes.
- Representation rank or variance collapses, or fixed-teacher drift exceeds the
  precommitted bound.
- Auxiliary gradients dominate the trunk update, cause non-finite steps, or
  oppose both task gradients.
- Policy/Q learning or fixed-opponent strength regresses repeatedly.
- Successor target encoding makes wall-clock efficiency materially worse without
  compensating strength.
- D6 parity fails anywhere in the auxiliary path.

Excellent auxiliary diagnostics without replicated playing-strength or
learning-speed improvement are a negative result. The predictor is discarded at
deployment, so representation benefit must appear through the ordinary network.

## Owner decisions required before Phase 0

### 1. Absolute transition term

Recommended: keep its weight at zero. The centered residual objective isolates
which consequences depend on the candidate and prevents phase prediction from
dominating.

Alternative: add a separately weighted absolute successor-delta term to teach
the common within-turn or handoff transition as well. This broadens the claim
from action discrimination to full one-step latent dynamics and reintroduces a
large easy component.

### 2. Action-null arm

Recommended: permute candidate markers among successors within each source. It
preserves marker count, predictor structure, target encoding, and compute while
destroying the correct action-target relationship.

Alternative: remove the marker entirely. This is simpler but changes the
predictor input distribution and makes the null arm less tightly matched.

### 3. Evidence budget

Recommended: use one short four-arm safety pilot, followed—only after it passes—
by three independent seeds for each of control, action-null, and action-effect.
Retain predictor-only in the replicated stage if its pilot does not track the
ordinary control closely.

Alternative: stop after a single control/treatment pilot. This is cheaper, but
its outcome can guide engineering only; it cannot establish a causal strength
benefit.

### 4. Probe checkpoint

Record the exact checkpoint path and SHA-256 from
`runs/klent/axis-gine/s4-from-mc25-tau16-alpha001-full-batch2048/checkpoints/`.
MC25 is lineage, not the automatic probe or branch point.

## Long-term boundary

If action-effect JEPA succeeds, later work may study multiple representation
depths, better counterfactual coverage, or using predicted changes as an
additional policy/Q feature. None of those follows automatically from the
training-only result.

Explicit strategic planning remains the responsibility of Gumbel MCTS over the
exact Rust engine. The action-effect auxiliary succeeds if it gives that planner
a better policy/value evaluator—not if it becomes another approximate planner.
